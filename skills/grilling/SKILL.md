# Grilling

사용자의 계획에서 숨은 가정·실패 조건·비싼 결정을 찾아, 답에 따라 다음 갈림길을 탐색한다. 질문 수를 채우기 위한 인터뷰는 하지 않는다.

## 질문 전에 조사

대상 프로젝트의 AGENTS.md를 읽는다. 위키가 있으면 index → overview → 최신 log → 관련 페이지를 읽고 필요한 문서·코드를 조사한다. 스스로 확인할 수 있는 것은 질문하지 말고 근거와 함께 짧게 공유한다.

남은 결정을 의존관계와 되돌리기 비용에 따라 정렬한다. 목적·성공 기준, 데이터 손실, 외부에 나가는 값, 사용자에게 보이는 약속처럼 결과가 큰 것부터 다룬다. 이미 사용자가 정한 것은 다시 묻지 않는다.

## 한 번에 하나

한 질문의 답을 받은 뒤 다음 질문으로 간다. 가능한 경우 2~3개 선택지와 권장안을 먼저 제시하고, 선택했을 때 화면·데이터·일정에 생기는 결과를 설명한다. 자유 응답도 허용한다. 여러 설계 결정을 한 질문에 묶지 않는다.

질문 도구는 현재 세션에서 실제 제공되는 것과 사용 가능한 모드를 확인한다.

- `request_user_input`은 현재 모드에서 허용되는 경우에만 쓴다.
- 비동기 질문 도구가 있으면 질문 하나를 보내고, 답을 기다리는 동안 그 결정과 독립적인 조사만 계속한다. 무응답·기본 선택·시간 경과는 동의가 아니다.
- 사용 가능한 질문 도구가 없으면 짧은 일반 질문 하나를 남기고 답을 기다린다.
- 도구의 실제 스키마에 없는 preview/description 필드를 만들어 넣지 않는다. 시각 비교가 필요하면 지원되는 표나 그림으로 질문 전 배경을 제공한다. 질문과 선택지를 텍스트와 도구로 중복하지 않는다.

사용자의 이해 수준에 맞춘다. 상황 설명은 짧고 구체적으로, 질문은 사용자가 볼 결과 중심으로 쓴다. 반문이나 어려움의 신호가 있으면 쉬운 예시로 다시 구성한다.

## 합의와 종료

몇 가지 결정이 쌓이면 확정 사항·남은 갈림길을 짧게 요약한다. 사용자가 중단하거나 범위를 줄이면 따른다. 결정이 충분하면 계획·성공 기준·남은 가정·검증 방법을 정리하고 사용자에게 합의 여부를 확인한다. 단순 인터뷰 요청을 구현 권한으로 확대하지 않는다. 이미 명확한 실행 지시를 받았고 필요한 결정이 해소됐다면 같은 승인을 다시 요구하지 않는다.

계획의 기록은 요청된 문서 또는 프로젝트의 운영 규칙에 따른다. 위키에 기록한다면 사용자 결정과 권고안을 구분하고 관련 페이지·index·log를 갱신한다. 읽기 전용 인터뷰에서는 파일을 쓰지 않는다. Jira 이슈 생성이나 외부 게시를 자동으로 수행하지 않는다.
