# Wiki Lint

기계 점검 다음에 실제 내용 검토를 한다. 기본은 읽기 전용이다. 사용자가 이미 수정을 요청했으면 그 범위의 근거 있는 수정을 진행하며 같은 허가를 반복해서 묻지 않는다. 해결할 수 없는 의미 충돌만 사용자 판단을 받는다.

## 대상 확인

루트 AGENTS.md와 연결된 위키 스키마를 읽고 index → overview → log 최신 항목을 확인한다. 실제 위키 루트·원본 루트·제외 규칙을 결정한다. 수리엔 등 특정 도메인·하드코딩된 경로를 가정하지 않는다.

## 기계 점검

기존 프로젝트의 린터가 있으면 스키마에 맞는지 확인해 사용한다. 없으면 이 스킬의 [검사 도구](scripts/wiki_lint.py)를 사용한다. 실행 전 [지원 범위와 한계](references/checks.md)를 읽는다.

```sh
python <skill-dir>/scripts/wiki_lint.py <wiki-dir> --source-root <workspace-root>
```

의존성 부재·읽기 실패를 정상 검사로 처리하지 않는다. 설치가 적절하지 않으면 직접 파일을 검사하고 수동 검토 범위를 밝힌다. 기존 스키마에 맞게 `--types`, `--hub`, `--exclude`를 사용한다. 허브에 이미 존재하는 잘못된 frontmatter를 면제로 숨기지 않는다.

스크립트가 검사하지 않는 원본 인벤토리는 실제 파일 목록과 catalog를 대조한다. 포함·제외 범위를 먼저 적용하고 미등록/미인제스트/부분 반영/읽기 실패를 구분한다. 전체 폴더를 조사하지 못하면 전체 집계가 검증됐다고 말하지 않는다.

## 의미 검토 — 생략하지 않기

index와 최근 ingest/결정 로그에서 영향받는 페이지를 찾아 직접 읽는다. 소규모는 전체, 대규모는 위험과 최근 변화 중심으로 검토하고 범위를 보고한다.

- **모순**: 동일 대상·시점·범위의 금액/날짜/상태/담당이 페이지별로 다른가. 현재 표와 아래 문단의 불일치를 확인한다.
- **낡은 주장**: 새 출처가 이전 주장을 실제로 대체했는가. 날짜가 오래됐다는 이유만으로 틀렸다고 하지 않는다. 지난 일정은 예정/완료/확인 불가를 구분한다.
- **구조와 합성**: 사례만 추가되고 요약은 그대로인지, 중요한 엔티티·개념이 없는지, 연결해야 할 페이지가 끊겨 있는지 살핀다.
- **공백**: 의사결정에 필요한 조건·근거·비교 항목 중 무엇이 비어 있는가. 영향이 큰 다음 질문을 세 개 이내로 제안한다. 외부 조사는 요청 범위나 별도 사용자 지시에 따른다.
- **충돌 사본**: 원본과 사본 양쪽을 읽고 차이를 보고한다. 점검 요청만으로 병합·이동·삭제하지 않는다. 병합 요청이면 양쪽의 유효한 변경과 미확정 부분을 보존하고, 사본 정리는 요청 범위에 있을 때만 한다.

## 보고와 수정

각 finding에 페이지/절 또는 줄, 주장, 양쪽 근거, 영향, 권장 조치를 적는다. 사실·의심·미확인을 구분한다. 검사한 페이지/원본 범위와 누락 범위, 기계 검사 결과, 의미 검토 결과를 분리한다. 결과 0건은 해당 범위에서만 유효하다.

기본 보고는 대화에 남긴다. 리포트 파일은 요청된 경우만 만든다. 읽기 전용이면 log도 변경하지 않는다. 수정한 경우에는 변경 이유와 남은 문제를 log 끝에 추가하고 관련 구조 검사·내용 대조를 다시 한다. 기계 검사 통과를 전체 위키 PASS라고 부르지 않는다.
