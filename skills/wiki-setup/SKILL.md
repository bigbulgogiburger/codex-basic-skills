# Wiki Setup

원본은 제자리에 두고, 재사용 가능한 지식을 `wiki/`에 누적하는 구조를 만든다. 스키마는 Codex가 직접 읽는 `AGENTS.md`에 둔다. 원본의 역할인 raw를 별도 `raw/` 폴더 생성 요구로 해석하지 않는다.

## 먼저 확인

1. 사용자가 지정한 루트와 적용되는 AGENTS.md를 읽는다. 대상이 불명확하면 현재 프로젝트 안에서만 위키 후보를 찾는다. 쓰기 대상 후보가 여러 개면 위치를 묻는다.
2. 기존 wiki/notes/vault 및 index·overview·최근 log, CLAUDE.md의 위키 규칙을 확인한다. 기존 위키가 있으면 그것을 채택하고 이름·위치를 유지한다.
3. 원본 폴더, 인벤토리 제외 경로, 파일명 관례를 실제 디렉터리에서 확인한다. 원본 내용은 필요 범위만 읽는다. 전체 인제스트를 요청받지 않았다면 전체 자료 합성을 시작하지 않는다.

## 구성

[AGENTS 템플릿](assets/AGENTS-wiki.md)을 읽고 대상에 맞춰 **루트 AGENTS.md에 병합**한다. 기존 지침은 보존하고 위키 운영 영역만 추가·수정한다. 기존 CLAUDE.md의 운영 규칙은 Codex용 AGENTS에 필요한 만큼 옮기거나 연결하되, Claude 전용 도구나 우선순위 선언을 그대로 복제하지 않는다.

필수 항목은 **작업 주제에 관계없이 매 작업 시작 시 index → overview → log 최신 항목부터 읽기**다. 이 규칙을 선택 사항으로 바꾸거나 단순 파일 링크로 대체하지 않는다. 기존 위키의 실제 경로로 적고, 파일이 없으면 부재를 알리고 사용 가능한 문서부터 읽게 한다.

새 위키에는 `wiki/{entities,concepts,sources}/`와 다음 허브를 만든다. 기존 파일은 덮어쓰지 않는다. 처음 생성할 본문 예시는 [초기 페이지](assets/starter-pages.md)에 있다.

- `index.md`: 모든 페이지의 링크와 한 줄 설명, 범주별 탐색.
- `overview.md`: 확인한 목적·범위·핵심 맥락과 근거. 자료가 없으면 미확인으로 남김.
- `catalog.md`: 원본 경로·인제스트 상태·반영 페이지·집계 범위와 제외 규칙. 읽지 않은 파일은 미인제스트. 조사하지 않은 범위는 미조사.
- `log.md`: 새로 생성한 것과 조사·합성 범위를 기록. 기존 로그에는 맨 끝에만 setup 항목 추가.

새 위키 기본값은 상대 Markdown 링크, 지식 페이지의 `type/updated/sources` frontmatter, 루트 기준 원본 출처 경로다. 기존 위키의 유효한 규칙이 다르면 유지한다. 별도 source-card는 독립적인 심층 요약이 필요할 때만 만든다.

## 운영 규칙의 구체화

- 새 입력은 기존 분류에 배치하고 파일명 관례를 따른다. 보관 중인 원본은 읽기 전용이다.
- catalog 제외 범위를 명시한다: 위키 자체, 에이전트 설정, 도구, 캐시, 임시 잠금 파일, 별도 생성 산출물. 업무상 정식 증빙으로 채택된 생성물은 명시적으로 포함할 수 있다.
- 질의는 위키부터 탐색하고 필요 시 원본으로 검증한다. 재사용 가치가 있는 분석의 환원 범위를 적는다. 읽기 전용 요청에는 위키·로그도 수정하지 않는다.
- 원본 기반 사실·사용자 결정·추론·미확인을 구분한다. 새 자료가 과거 주장을 바꾸면 현재 표·본문·연결된 요약을 함께 갱신하고 변경 이유를 남긴다.
- 외부 게시나 전역 스킬 설치는 setup에 포함하지 않는다.

## 검증

실제 AGENTS와 허브를 다시 열어 경로와 필수 시작 순서를 확인한다. 기존 원본·사용자 지침·로그가 보존됐는지 diff 또는 해시로 확인한다. wiki-lint가 설치되어 있으면 구조 검사를 실행하고, 없으면 새 링크를 직접 확인한다. 재실행 시 중복 섹션·폴더·불필요한 setup 로그를 만들지 않는다.

완료 보고에 생성/변경 경로, 채택한 원본 폴더·제외 범위, 실제 인제스트 범위, 미확인 사항을 적는다. 틀만 만든 것을 전체 자료 인제스트 완료라고 보고하지 않는다.
