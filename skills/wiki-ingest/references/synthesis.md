# 합성 규칙

## 현재 사실과 이력

예: 기존 표가 `검토 중 / 100`인데 새 체결 문서가 `체결 완료 / 120`이라면 새 문단만 붙이지 않는다. 관련 현재 상태표·본문·요약을 함께 바꾸고, 별도 이력 절에 `100 → 120, 변경 근거와 날짜`를 남긴다. 과거 로그의 100은 당시 기록이므로 수정하지 않는다.

새 자료로 미결이 해소되면 해결 상태와 근거를 남긴다. 행을 지워 해결 과정을 없애지 않는다. 명시적인 superseded 관계가 없는 두 출처의 모순은 양쪽 출처·시점·대상을 비교하고 미해결로 표시한다.

## 최소 메타데이터

새 위키 기본값은 다음이다. 기존 스키마에 다른 타입·필드가 있으면 그것을 사용한다.

```yaml
---
type: concept
updated: 2026-01-15
sources:
  - "회의록/20260115_제품회의.md"
---
```

`sources`의 로컬 경로는 위키 파일 위치가 아니라 **업무 루트 기준**이다. 본문 링크는 현재 Markdown 파일 기준 상대 경로다. 날짜는 실제 작업일로 대체한다. 중요한 주장에는 원본의 절·쪽·표를 함께 적는다.

## 인벤토리와 탐색

- catalog는 원본이 어디 있고 어디까지 반영됐는지 보여준다. 파일 존재와 내용 반영 완료는 다르다.
- index는 지식 페이지로 진입하는 콘텐츠 지도다. 원본 목록을 그대로 중복하지 않는다.
- log는 무엇을 바꾸었고 왜 바꾸었는지, 무엇을 확인하지 못했는지 보여주는 시간순 기록이다.
- 원본 하나가 여러 페이지에 합성되거나 여러 원본이 한 페이지에 합성될 수 있다. 파일 수를 페이지 수로 추정하지 않는다.
- 같은 대상을 다른 이름으로 여러 페이지에 만들지 않는다. 기존 명칭·별칭을 먼저 검색한다.

## 부분 실패와 동시 수정

쓰기 직전에 대상 파일을 다시 읽거나 처음 읽은 해시와 비교한다. 변경되었으면 새 내용을 바탕으로 최소 patch를 다시 계산한다. 오래된 전체 파일을 덮어쓰지 않는다. 로그 쓰기에 실패하면 현재 파일을 다시 확인하고, 계속 실패하면 미기록 내용을 완료 보고에 남긴다. 실패를 숨기는 자동 재배치나 임시 페이지의 무한 생성은 하지 않는다.
