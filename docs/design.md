# 패턴 분석과 Codex 적용

## 공통 원칙과 선택 사항

「LLM Wiki — A pattern for building personal knowledge bases using LLMs」는 고정 디렉터리 표준이 아니라 도메인에 맞게 구체화할 아이디어 문서다. 이 패키지는 개인·연구·학습·팀 문서에 공통으로 적용하며, 특정 조직의 폴더 체계나 내부 도구를 요구하지 않는다. 여기서는 다음을 유지한다.

| 원문 원칙 | 이 저장소의 구현 |
|---|---|
| 원본·위키·스키마 3계층 | 기존 업무 폴더·`wiki/`·`AGENTS.md` |
| 원본은 불변 | 새 자료 최초 배치는 가능; 보관 원본 수정·재배치·삭제는 별도 요청 범위 |
| 지속적으로 축적하는 합성 | 원본 요약만 쌓지 않고 엔티티·개념·현재 상태·종합 판단까지 갱신 |
| Ingest / Query / Lint | ingest·lint 스킬 + AGENTS의 query 규칙 |
| 콘텐츠 색인과 시간 로그 분리 | `index.md`와 append-only `log.md` |
| 좋은 답변의 위키 환원 | 운영 스키마에 허용 범위를 명시; 읽기 전용 요청은 우선 |
| 도메인별로 조정 가능한 구성 | 기존 경로·대소문자·frontmatter·링크 형식 보존 |

`catalog.md`, `overview.md`, 필수 시작 순서, 원본 파일의 배치·파일명 정리, 상태표와 본문 동시 갱신은 실제 업무 위키에서 가져온 운영 선택이다. Karpathy가 특정 폴더명이나 이 네 파일을 의무화했다고 주장하지 않는다. Obsidian, 임베딩, 검색 서버, Git, source마다 별도 카드 만들기는 필수가 아니다.

## 기존 스킬을 그대로 복사하지 않은 이유

- 범용 llm-wiki의 강제 `raw/`, 루트 대문자 INDEX/LOG, 원본마다 1:1 카드, 모든 편집의 sentinel 제한은 기존 업무 위키에 불필요한 이주를 만든다. 이 패키지는 기존 구조를 먼저 읽는다.
- Claude의 디바이스 브리지 파일 업로드·커밋·캐시 우회 규칙은 로컬 Codex 파일 작업에 맞지 않는다. 실제 파일 읽기와 크기·해시 검증으로 바꾼다. Git 커밋은 ingest의 필수 요건이 아니다.
- 기존 wiki-lint의 도메인 분기와 자동 충돌 사본 이동은 범용 기본값으로 채택하지 않는다. 검사는 읽기 전용이고 수정 요청의 범위가 있을 때만 고친다.
- 기존 grilling의 `AskUserQuestion`, 지원되지 않는 `preview` 필드, 항상 `request_user_input`을 호출하는 규칙은 현재 도구의 사용 가능 모드·스키마를 확인하는 방식으로 바꾼다.
- grill-me는 다른 플러그인의 slash command에 의존하지 않는다. grilling이 없을 때도 핵심 인터뷰를 수행한다.

## 해석상 주의

최근 로그는 최신 작업과 미결을 찾는 진입점이다. 사실의 근거는 원본이며, 로그의 날짜가 더 최신이라는 이유만으로 증거가 약한 주장을 확정하지 않는다. `updated` 날짜가 오래됐다는 사실만으로 내용이 틀렸다고 판단하지 않는다.

초기 setup과 인제스트 완료를 구분한다. 원본을 열지 않고 내용 요약·총계·완료 상태를 만들어 내지 않는다. 파일 인벤토리는 실제 범위와 제외 규칙을 표시하며, 원본 파일 수와 합성 페이지 수는 다를 수 있다.

## 검증 시나리오

1. 빈 폴더 setup: AGENTS 시작 규칙과 네 허브 생성, raw 폴더 없음, 근거 없는 개요 없음.
2. 기존 업무 폴더 setup: 원본 해시·경로, 기존 AGENTS 사용자 영역·로그 보존. 재실행 diff 없음.
3. 기존 `notes/` 또는 `INDEX.md` 위키: 현재 이름으로 링크·시작 규칙 치환, 두 번째 wiki 생성 없음.
4. 새 문서 ingest: 기존 폴더 관례로 배치, 다른 내용의 동명 파일 덮어쓰기 없음, 현재 표와 본문 동시 갱신.
5. 위키만 반영/배치만/검토만: 각 요청 밖의 파일 수정 없음.
6. lint: 코드 블록 가짜 링크 제외, 실제 깨진 링크 발견, 검토 범위·읽기 실패 보고, 원본 불변.
7. 의미 검토: 새 문단과 오래된 상태표의 불일치 발견. 과거 기록은 현재 오류와 구분.
8. 인터뷰: 코드에서 확인 가능한 질문 생략, 하나의 결정만 질문, 무응답을 동의로 간주하지 않음.

위 목록은 동작 검증 기준이다. 자동 테스트는 검사 스크립트의 구조적 동작을 검증하며, 전체 Codex 대화 시나리오를 실행했다는 뜻은 아니다.
